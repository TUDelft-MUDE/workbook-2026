On their first visit, readers see a prompt to enable changelog notifications or dismiss it; dismissal is remembered in the browser. The bell button at the left of the top bar's right-hand buttons opens a menu with an Enable/Disable notifications item, styled like the other header menu items. Browser permission is requested only when a reader chooses Enable. If the browser blocks notifications or does not show a permission prompt, readers can check notification permissions in the browser's site settings. Guidance about blocked notifications appears on the first page of a tab session and can be closed; it also appears when a reader tries to enable blocked notifications. The book checks for updates once when opened in a new browser tab session; if the check fails, it retries when navigating to another page. Pages opened later in the same session silently mark the current changelog commit as seen, so a reader who already saw an update is not notified of it on the next visit. It cannot send notifications when all workbook pages are closed. Preferences are stored in the browser. JavaScript is required, and browser or operating system settings may also block notifications.

Notifications use a service worker scoped to `_static/changelog-notifications-worker/` so they can be displayed on Android without controlling workbook pages. A secure connection and browser support for notifications and service workers are required; registration or delivery can still fail. On iOS and iPadOS 16.4 or later, notifications require a Home Screen web app rather than a browser tab. In Safari, use Share > Add to Home Screen, turn on Open as Web App if offered, and open the workbook from the Home Screen before enabling notifications. The extension adds Apple's web-app-capable metadata so older supported iOS versions can open saved pages as web apps; an existing setting is left unchanged. Home Screen web apps have separate browser storage, so notification preferences must be enabled there. Browser availability and spam warnings vary by device; iOS notification delivery has not been verified on a physical device.

If a reader changes browser permission to allowed and reloads or navigates within the same tab, the menu opens once to remind them to select Enable notifications if they have not already enabled them. The reminder can be closed and does not enable notifications on its own.

The local `changelog_notifications` Sphinx extension uses the latest Git commit affecting `book/changelog.md` as its fingerprint. Git and the document's full commit history must be available when building; uncommitted changes do not change the fingerprint. To use another document, set `changelog_notifications_docname` in the Sphinx configuration to its document name (without the file extension). Notifications reflect changes in the deployed book, not unpublished source changes. Existing subscribers are silently re-baselined when moving from content fingerprints to commit hashes, so an update pending at that point may not trigger a notification.

The `changelog-article-header-buttons.html` component in `html_theme_options.article_header_end` renders the notification button inside the Sphinx Book Theme's header button group, before the other buttons. It mirrors the theme's `article-header-buttons.html` component, so update it if the theme's button rendering changes.
